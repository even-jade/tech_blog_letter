## [AI가 팀 규칙을 지키도록 하는 방법](https://toss.tech/article/52631)
- 회사: 토스 (토스뱅크)
- 본문 요약: Coding Agent가 팀 컨벤션을 자꾸 놓치는 문제를 다룬 글입니다. AGENTS.md 같은 Global Instruction에 규칙을 적어두면 세션 초반엔 지키다가 길어질수록 무시하는 **Lost in the Middle** 현상이 나타났고, 세세한 규칙을 전부 적으면 Context만 부풀어 오히려 준수율이 떨어졌습니다. 해결책은 Agent Loop 안에 **Feedback Loop를 하나 더 심는 것** — 예전 "LLM → Linter → 에러 메시지 재주입" 패턴에서 Linter 자리에 팀 컨벤션을 넣은 발상입니다. 이를 구현한 플러그인이 `pfmls-stylepack`(Stylepack)으로, 규칙 파일 하나에 발동 조건(file_pattern, code_regex, exclude_pattern)과 주입 문장(context_injection)을 함께 둡니다. 주입 시점은 두 곳입니다. (1) **파일 작성 직후 Hook**: 방금 쓴 파일 본문을 정규식·파일명 패턴으로 훑어 관련 규칙 후보를 빠르게 골라 최대 2개, 같은 규칙은 세션당 1회만 주입(AI로 관련성 판정을 붙였더니 요청당 10초가 늘어 폐기). (2) **작업 종료 직전**: 이번 변경 전체(git diff)를 보고 최대 4개를 주입해, 파일 하나만 봐선 안 보이는 "서비스가 인터페이스 대신 구현체에 의존" 같은 위반을 잡는 마지막 안전망. 세션 시작 시엔 레포의 pyproject.toml/build.gradle을 보고 언어별 팀 Context를 넣고, 규칙은 각 레포에 복사하지 않고 중앙 저장소에서 주기적으로 당겨와 템플릿이 "복사되는 순간부터 늙는" 문제를 피했습니다. 규칙이 뜬 순간을 모두 로그로 남겨 Stylepack 자체도 개선했는데, `{a.b: ...}` dict를 잡으려던 정규식이 f-string 포맷 `{item.score:.2f}`에 21개 세션에서 오탐(코드 변경 0건)한 것을 콜론 뒤 공백 하나로 고친 사례, N+1처럼 `.map`/리스트 컴프리헨션 등 형태가 무한히 늘어나는 문제는 규칙 대신 **상시 Context**로 옮긴 판단이 소개됩니다. 새 규칙은 PR 리뷰에서 반복되는 코멘트(예: `@dataclass`에 캐시·조회 로직을 넣은 서비스 클래스)를 묶어 승격시킵니다.
- 주목할 point: 문제를 "무엇을 알려주느냐"가 아니라 **"언제, 몇 개를 알려주느냐"**로 재정의한 것이 핵심입니다. 코드 모양으로 판정되는 규칙은 Hook, 실행돼야 드러나는 문제는 상시 Context라는 분류 기준과, Hook은 AI 없이 정규식으로만 후보를 좁히고 최종 판단은 에이전트에 맡기는 속도-정확도 트레이드오프는 Claude Code/Codex 훅을 설계하는 팀이 바로 가져다 쓸 수 있습니다.
