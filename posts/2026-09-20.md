## [VPC 내 프라이빗 서비스에 AWS DevOps Agent를 안전하게 연결하기](https://aws.amazon.com/ko/blogs/tech/securely-connect-aws-devops-agent-to-private-services-in-your-vpcs/)
- 회사: AWS
- 본문 요약: AWS DevOps Agent(인시던트 해결·예방과 SRE 작업을 대신 수행하는 운영 에이전트)를 커스텀 MCP 서버, 셀프 호스팅 Grafana/Splunk, GitHub Enterprise/GitLab, 내부 문서 API처럼 퍼블릭 인터넷에 노출되지 않은 VPC 내부 서비스에 연결하는 '프라이빗 연결(Private Connections)' 기능을 소개하는 글입니다(2026년 4월 영문 원문을 현행 사용자 가이드 기준으로 갱신해 번역). 프라이빗 연결은 내부적으로 Amazon VPC Lattice를 사용해 서비스 관리형 리소스 게이트웨이를 만들고 지정한 서브넷에 ENI를 프로비저닝하며, 에이전트 트래픽은 이 ENI를 진입점으로 대상 서비스의 IP 또는 DNS 이름으로 라우팅됩니다. 계정에 생성되는 리소스는 서브넷의 ENI뿐이고, 리소스 게이트웨이는 계정에서 읽기 전용이며 AWSAIDevOpsManaged 태그 리소스로만 범위가 제한된 서비스 연결 역할이 관리합니다. 보안 설계는 퍼블릭 인터넷 노출 없음, 서비스 제어형 리소스 게이트웨이(CloudTrail로 감사 가능), 사용자 소유 보안 그룹으로 아웃바운드 제어, 최소 권한 역할, DNS 해석 모드(Public / In VPC — 프라이빗 호스팅 영역 전용 이름도 퍼블릭 레코드 없이 해석) 다섯 층으로 정리했습니다. 콘솔(Capability providers → Private connections)과 CLI(`aws devops-agent create-private-connection`)로 VPC·서브넷(가용 영역당 1개, 다중 AZ 권장)·IP 타입·보안 그룹(최대 5개)·포트 범위(최대 11개)·호스트 주소·DNS 해석 모드·프라이빗 CA 인증서 체인을 지정해 생성하는 절차, 최대 10분 걸리는 생성 상태 확인, Create failed 시 점검 항목(서브넷 IP 여유, VPC Lattice 할당량, 제한적 IAM 정책)을 단계별로 안내합니다. 대표 예제로 프라이빗 서브넷의 셀프 호스팅 Grafana를 Viewer 서비스 계정 토큰으로 계정 수준 등록(register-service, `--private-connection-name` 지정) 후 Agent Space에 연결(associate-service)하고, 선택적으로 Grafana 웹훅 contact point를 Agent Space 웹훅 URL로 지정해 알림 발생 시 에이전트가 자동 조사를 시작하게 하는 구성을 다룹니다. 호스트 주소는 VPC Lattice의 DNS 해석용이고 통합 등록 시의 엔드포인트 URL은 Host 헤더/SNI에만 쓰이므로, ALB 하나를 호스트로 둔 단일 프라이빗 연결에 Grafana·MCP 서버 등 여러 통합을 서로 다른 호스트네임으로 묶고 ALB 호스트 기반 라우팅으로 분기하는 패턴도 설명합니다. 이미 VPC Lattice를 운영 중이라면 기존 리소스 구성 ARN을 지정하는 자체 관리형(selfManaged) 모드로 수명 주기·계정 간 공유·접근 로그·제로 트러스트 제어를 직접 가져갈 수 있고, 마지막으로 비용 방지를 위한 삭제 절차를 안내합니다.
- 주목할 point: AI 운영 에이전트를 사내 프라이빗 시스템에 붙일 때 퍼블릭 엔드포인트나 VPN 없이 VPC Lattice 리소스 게이트웨이 + 사용자 보안 그룹만으로 경로를 여는 구조, DNS 해석(호스트 주소)과 TLS Host/SNI(엔드포인트 URL)를 분리해 하나의 프라이빗 연결로 여러 통합을 다중화하는 설계, Public/In VPC DNS 모드와 프라이빗 CA 체인 순서(리프→중간→루트) 같은 실전 함정, 그리고 기존 Lattice 사용자를 위한 자체 관리형 모드가 에이전트 도입을 검토하는 플랫폼·SRE 팀에 참고할 만합니다.
