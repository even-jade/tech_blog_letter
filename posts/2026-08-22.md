## [Claude Code로 만든 데이터 분석 에이전트, Amazon Bedrock AgentCore로 프로덕션 배포하기](https://aws.amazon.com/ko/blogs/tech/claude-code-to-bedrock-agentcore/)
- 회사: AWS
- 본문 요약: 로컬 Claude Code에서 검증을 마친 이커머스 매출 분석 에이전트를 코드 로직 변경을 최소화한 채 Amazon Bedrock AgentCore로 이전하는 전 과정을 다룹니다. 핵심 아이디어는 Claude Code를 구성하는 세 요소를 AgentCore 관리형 서비스에 1:1로 대응시키는 것입니다 — stdio MCP 서버는 AgentCore Gateway(관리형 원격 MCP 엔드포인트 + Cognito JWT 인증), 로컬 에이전트 실행은 AgentCore Runtime(서버리스 컨테이너, 세션 격리, 자동 확장), 외부 검색은 AgentCore Web Search(API 키 없이 SigV4 인증)로 옮깁니다. Skill(`.claude/skills/sales-report/SKILL.md`)은 별도 서비스 없이 Runtime 컨테이너에 그대로 포함돼 리포트 형식이 유지됩니다. 로컬과 프로덕션을 잇는 다리는 Claude Agent SDK로, `setting_sources=["project"]`를 주면 `.claude/settings.json`, `.mcp.json`, `.claude/skills/`를 Claude Code와 동일하게 읽어 비대화형으로 실행합니다. 실습은 가상 쇼핑몰 AnyCompany의 6개월치 주문 데이터(주문 4,512건, 매출 약 6.2억 원)를 소재로 4단계(로컬 에이전트 구성 → Gateway 전환 → Runtime 배포 → Web Search 연동·검증)로 진행되며, us-east-1 리전과 Claude Sonnet 4.6 모델 액세스를 전제로 합니다. 전체 예제 코드는 `aws-samples/sample-agentic-ai-acceleration-kr` 리포지토리에 있습니다.
- 주목할 point: "프로덕션용으로 처음부터 다시 작성"하지 않는다는 것이 이 글의 실무적 핵심입니다. Claude Agent SDK가 stdio MCP와 원격 HTTP MCP를 동일하게 다루기 때문에, 전환 시 바뀌는 것은 MCP 서버 등록 방식(`{"type":"http","url":GW_URL,"headers":{"Authorization":...}}`)뿐이고 SQL을 포함한 도구 로직은 그대로입니다. Gateway 전환도 기계적이어서 `@mcp.tool()` 데코레이터의 입력 스키마를 Gateway 타깃의 inline `toolSchema`로 옮기고 함수 본체를 Lambda 핸들러로 이식하면 됩니다. 컨테이너 구성에서 걸리기 쉬운 두 가지 함정이 명시돼 있습니다 — Claude Agent SDK가 내부적으로 `claude` CLI를 실행하므로 Dockerfile에 Node.js와 `@anthropic-ai/claude-code`를 설치해야 하고, Runtime 파일 시스템은 `/tmp` 외 읽기 전용이라 `HOME=/tmp` 설정이 필요합니다. 관측성에도 함정이 있는데, 모델 호출이 `claude` CLI 서브프로세스 안에서 일어나 토큰·비용이 담긴 `gen_ai.*` LLM 스팬이 자동 계측에 잡히지 않습니다. SDK가 스트림 끝에 반환하는 `ResultMessage`(토큰·비용·레이턴시)로 직접 `gen_ai` 스팬과 CloudWatch 커스텀 메트릭을 기록하는 우회법을 제시하며, 프롬프트 원문 수집은 PII 때문에 옵트인 권장입니다. 보안 측면에서는 Gateway 리소스 기반 정책에 `SourceAccount`/`SourceArn` 조건을 걸어 범위를 한정하고, `gateway.json`에 Cognito 클라이언트 시크릿이 들어가므로 커밋 금지(프로덕션은 Secrets Manager 권장)라는 점을 짚습니다. 실습 후 과금(Bedrock 토큰, Runtime 실행 시간, Lambda, ECR)을 막으려면 `agentcore destroy` 외에 Cognito 사용자 풀·ECR·CodeBuild·IAM 역할·로그 그룹은 콘솔에서 따로 지워야 합니다.
