## [Cilium, Under the Hood #2: eBPF로 들여다보는 Kubernetes 네트워크의 동작 원리](https://on.com2us.com/tech/cilium-ebpf-under-the-hood-part2/)
- 회사: 게임빌컴투스플랫폼 (컴투스)
- 본문 요약: 1편(Identity·Endpoint·IPAM, Socket LB 기반 East-West 로드밸런싱)에 이어 North-South 로드밸런싱, Hubble 관측성, Cluster Mesh 멀티클러스터를 KIND 실습과 tcpdump 패킷 분석으로 다룹니다. 외부 트래픽은 connect() 후킹이 불가능해 진입 노드의 tc(tcx) 계층에서 DNAT하며, SNAT 모드(기본, 응답이 진입 노드를 거쳐 홉 추가·클라이언트 IP 소실)와 DSR 모드(클라이언트 IP 보존·응답 경로 단축, IPIP/IP Option/Geneve 디스패치)를 패킷 캡처로 비교합니다. eBPF 모드에서는 bpf_redirect_peer()로 파드 netns에 직접 주입되어 호스트의 lxc 인터페이스에 요청 패킷이 캡처되지 않는 이유, DSR IP Option(type 154)에 담긴 원래 노드 정보로 응답 소스를 복원하는 과정을 짚습니다. 이어 Hubble(Server/Relay/UI)로 라벨·L3/L4·L7(Envoy 우회) 정책의 FORWARDED/DROPPED 판정을 관찰하고, 공유 CA 구성 후 cilium clustermesh connect로 두 클러스터를 묶어 global 서비스 annotation 기반 백엔드 병합과 레플리카 0 스케일 시 원격 클러스터로의 failover, affinity(local/remote/none) 제어까지 실습합니다.
- 주목할 point: "왜 tcpdump에 이 패킷이 안 보이는가"를 eBPF helper 동작으로 설명하는 식의 패킷 단위 분석이 강점입니다. L7 정책을 걸면 트래픽이 유저스페이스 Envoy를 왕복해 Socket LB 이점을 잃는다는 비용, Cluster ID가 Identity 비트에 반영돼 클러스터 간 Identity 충돌을 막는 구조, Cluster Mesh 연결 시 CA 불일치 오류와 해결 절차 등 실제 구축 시 부딪히는 지점을 함께 정리해 둔 점이 유용합니다.
