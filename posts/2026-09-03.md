## [삼성 계정 AIOps: AgentCore기반 멀티 에이전트 운영 자동화 여정](https://aws.amazon.com/ko/blogs/tech/agentcore-aiops-samsung-1/)
- 회사: AWS (삼성전자 삼성계정 서비스 SRE팀 기고)
- 본문 요약: 약 21억 사용자를 연결하는 삼성계정(Samsung Account)의 SRE 조직이 멀티 리전·다계정 환경의 운영 복잡도를 풀기 위해 Amazon Bedrock AgentCore 위에 구축한 Agentic AIOps 시스템의 설계편입니다. 서비스가 커질수록 스택이 쌓이고 변경 한 건의 영향도 분석·보안 점검·비용 관리가 비례해 늘어나는데, 대고객 서비스라 원인 분석부터 조치까지 매우 짧은 시간 안에 끝나야 한다는 문제 정의에서 출발합니다. 아키텍처는 **책임을 도메인으로 나눈 3계층 멀티 에이전트**로, Orchestrator 아래에 장애 분석·변경 추적·보안 점검·비용 최적화 등 전문 에이전트가 계층적으로 협업하고, 두 개의 입구(대시보드·채팅)가 하나의 처리 경로로 수렴하며, 부품을 더하듯 에이전트를 늘릴 수 있는 구조입니다. 이를 지탱하는 네 개의 필라로 AgentCore Runtime(멀티 에이전트 실행 환경), AgentCore Observability(3계층 호출 흐름 끝까지 추적), AgentCore Evaluation(품질을 지표로 관리), Bedrock Guardrails(Orchestrator 레벨에서 민감정보 차단)를 제시합니다. 자율운영 성숙도 모델은 Level 1(멀티 에이전트가 함께 분석) → Level 2(계획하고 승인 후 실행)로 단계적으로 넓혀 왔고, 지속 가능한 운영 모델로 Skill(업무 지식을 문서로 자산화하고 스스로 고도화), AgentCore Memory(별도 DB 없이 운영 지식 축적), 스케줄러(권한을 늘리지 않고 자동화 확장)를 소개합니다. 참고 문헌으로 블랙보드 아키텍처 기반 LLM 멀티 에이전트 논문들을 인용합니다.

Runtime·Observability·Evaluation·Guardrails를 "필라"로 먼저 세운 순서도 눈여겨볼 만합니다 — 에이전트 수를 늘리기 전에 추적·평가·차단 장치부터 갖춰야 운영 가능한 시스템이 된다는 메시지입니다. 스케줄러로 권한 확대 없이 자동화를 넓힌다는 발상, 반복 업무를 Skill 문서로 자산화한다는 접근은 Claude Code 등 다른 에이전트 환경에도 그대로 옮길 수 있습니다.

## [삼성 계정 AIOps: AgentCore기반 AlOps의 실전 활용과 자율성 확장](https://aws.amazon.com/ko/blogs/tech/agentcore-aiops-samsung-2/)

- 본문 요약: 1부에서 설계한 멀티 에이전트 AIOps가 실제 운영 현장에서 어떻게 쓰이는지 다루는 활용편입니다. 시스템 기능으로 MAIN 탭 대시보드, 에이전트별 상세 정보, 블랙보드 기반 작업 흐름, 변경·배포 이력 추적을 소개하고, 실제 활용 사례로 **장애 알람 실시간 분석, 인프라 변경 영향도 분석, 월간 리포트 자동화, 원격 긴급 작업 수행**을 보여줍니다. 도입 전에는 알람이 오면 콘솔을 하나씩 열어 지표·로그를 확인하고 과거 사례를 기억에서 더듬었지만, 지금은 알람 시점에 이미 교차 분석된 결과가 함께 도착합니다. 다만 "업무량이 줄었다"는 절반만 맞는 설명이라며, 기존 SRE 실행 업무가 효율화된 자리에 **에이전트를 직접 개발·고도화하는 에이전틱 엔지니어링(Agentic Engineering)** 업무가 새로 생겼다고 짚습니다 — 잘못 판단한 사례를 분석해 프롬프트와 판단 기준을 다듬고, 반복 작업을 Skill 문서로 등록하고, 새 도메인용 도구와 평가 지표를 설계하는 일은 모두 사람 몫입니다. Level 3·4로 나아가기 위한 방향으로 프로세스 개선을 통한 수행 영역 구분과 단계별 확산, 수행 데이터의 신뢰 지표 정량화, 신뢰 지표 기반 저위험·정형화 작업의 Level 3 전환 확대, 모델 발전에 맞춘 통제 수위 조정을 제시하며 "믿을 수 있는 만큼만 맡기고, 맡긴 만큼 검증해 신뢰를 넓혀간다"로 마무리합니다.
- 주목할 point: **운영자의 역할이 "정보 수집"에서 "검증과 최종 판단"으로 이동했다**는 정리가 가장 현실적인 결과 보고입니다. 화려한 자동화가 아니라 더 빠르고 근거 있는 판단이 가치라는 표현은, AIOps 도입 목표를 세울 때 좋은 기준이 됩니다. 두 번째로 **에이전틱 엔지니어링이라는 새 업무의 등장**을 솔직하게 인정한 점 — 자동화로 사람이 사라지는 게 아니라 일의 종류가 바뀐다는 걸 조직 리더가 미리 알아야 인력 계획이 틀어지지 않습니다. 세 번째는 Level 3 전환 조건을 "신뢰 지표 정량화"에 걸어둔 것으로, 실행 권한 확대를 감(感)이 아니라 수행 데이터로 결정하겠다는 원칙입니다.
